# Orchestration validation

The automated fixture suite verifies routing and runtime mechanics. Skill selection and delegation decisions also depend on the active host/model, so use these requests when evaluating a new model or instruction change in a disposable project with the plugin installed and configured.

The executable ordinary-prompt evaluation is now `scripts/dev/evaluate-orchestration.mjs`; see [terminal task management](task-management.md) for commands, artifact checks, evidence capture and limitations. Its grading fixtures pass, but a live run remains blocked by the Windows shell launcher. This does not establish spontaneous delegation in either host.

| Request | Evidence to inspect |
| --- | --- |
| Fix a typo in one documentation sentence. | The parent makes the small change without unnecessary workers. |
| Implement two independent functions with explicit file ownership and acceptance tests. | The host reads configuration, selects the executor role, provides bounded assignments, and verifies the resulting files. Independent workers can overlap within the configured limit. |
| Investigate an ambiguous cross-component failure and fix it. | A planner or explorer supplies evidence when useful; the parent chooses the direction and continues through implementation and checks. |
| Compare two concrete implementation options before making changes. | The advisor supplies a bounded second opinion without editing; the parent makes the decision. |
| Fix this directly without delegation. | The user's instruction overrides auto mode. |
| Continue the previous worker's assignment with one correction. | The parent reuses the worker/conversation and preserves the assigned scope. |

Repeat a delegation case with `automation.mode: manual`: ordinary requests should remain in the parent, while an explicit delegation request may invoke workers. Repeat with an unavailable executor: the parent should report the failure and avoid silently claiming that model ran or broadening permissions.

Record the host version, parent model, role models, prompt, actual agent/tool calls, produced artifacts, checks, and unfinished work. Test native and cross-harness routes separately. A passing CLI fixture test or a model's claim that it delegated does not establish successful automatic orchestration.

Current automated coverage lives in `tests/orchestration.test.mjs`, `tests/delegation.test.mjs`, and `tests/packaging.test.mjs`. Authenticated CLI smoke tests and isolated plugin installation tests remain opt-in; the behavioral requests above are a manual evaluation protocol, not claimed benchmark results.

Provider coordination adds `tests/provider-adapters.test.mjs` and `tests/task-coordination.test.mjs`. These verify JSON-RPC initialization, pinned context/integrity checks, ordered events from concurrent processes, scoped approval decisions, controls, result parsing and completion cursors. Supervisor tests verify shared revisions and monitor advice after failed evidence without bypassing acceptance.
